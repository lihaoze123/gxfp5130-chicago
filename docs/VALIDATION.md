# 验证证据与边界

本文件保留对后续开发有用的结论，实验原始文件放在本机私有回退包，未提交
指纹图像、校准、模板或 DLL。不同阶段用了不同匹配器，不能把分数混合比较。

## 预处理恢复

早期对照对同一组生成的类指纹输入，分别运行本地原厂 DLL 和 C 实现：

- 系数 map 在所测帧上的 5120 个位置逐项一致。
- 用原厂自己的 operands 回放 `(M*G + 4096) >> 13`，composition 逐项一致。
- 输出图像前 0–4 帧差异均在 ±1 灰阶内；稳态第 5–9 帧平均偏差约 1.0–1.6，
  最大偏差约 16–23。平均接近不代表逐像素相等。
- 已定位的残余差异包括 gain 的每项更新，以及首行 41 个低位 marker。
- 修复过 map 分母使用当前参考均值的四舍五入，以及“更新 gain 后再 compose”
  的顺序；reference fold/control 在输出后影响下一帧。

这些是生成输入上的 DLL 对照，不是所有真实皮肤、所有历史状态的完整等价
证明。旧记录中“every frame byte-exact”等简写过强，应以上述范围为准。
早期 SIGFM 实验也不能代表后来 Chicago matcher 的阈值或安全性。

## 真机原生匹配与 fprintd

2026-10-06 的独立 native Chicago 诊断：同指 directed pairs 23/24 接受，
异指 0/32；3 个样本录入后的 held-out 同指 2/2（64、48），异指 0/8。
这是独立诊断结果，不等于 fprintd 接入已经正确。

第一次接入后真实同指验证 0/3，分数 -4/-7/-7。发现了 identify-before-enroll
与单次初始化的手动诊断存在生命周期差异。修正空 gallery 快速返回、非空
identify 等待抬手；适配器合成差分检查确认同输入的特征、度量、gallery 字节
和最终分数构造一致。暗帧污染是合理解释，未直接隔离成唯一因果证据。

随后用户按说明完成一次重新录入及真实 fprintd 测试：

| 分组 | 匹配 | 拒绝 | 错误／超时 |
| --- | ---: | ---: | ---: |
| 同指 | 9 | 1 | 0 |
| 异指 | 0 | 10 | 0 |

同指得分：`32,-7,28,28,77,38,41,61,93,35`。
异指得分：`-4,-4,-4,-7,-6,-7,-4,-7,-7,-7`。
日志显示分数 77、61、93 的三次成功验证有学习更新及实际保存。
分组依赖用户按提示操作，没有独立测量手指身份。样本很少，不能据此计算
可信的 FAR／FRR 或宣称原厂 matcher parity。

用户后续反馈异指未见成功，同指基本可用，但姿态／位置覆盖仍有限。
纠正方向提示后尚未补做正式覆盖率实验；整理仓库不要求用户重新触摸。

## 本次仓库整理检查

- 新仓库自身构建 libfprint、fprintd、kernel、tools；运行时没有 DLL 后端。
- CTest 11 组通过，覆盖 native、OTP/FDT、matcher 和合成 chain。
  原匹配器的若干私有向量用例无输入时跳过，不计为 oracle 验证。
- 工具匹配／拒绝状态、正负分数和方向提示解析检查通过；三个打包入口可执行。
- NixOS 模块求值确认所有默认 PAM 服务及新定义服务均 `fprintAuth=false`；
  用户显式设置 `sudo.fprintAuth=true` 时该选择保留。
- 内核模块软件包在锁定 nixpkgs 的 6.18.36 内核上构建；本机先前实测内核
  为 6.18.54。模块按安装者的 `boot.kernelPackages` 构建，不能复用不同版本 ko。
- 没有部署新的系统配置，也没有重新做设备生物识别测试；上述 9/10、0/10 是
  已有实际测试记录，而非整理后重复测量。

## 后续验证应回答的问题

优先检查实际服务加载的库、probe 构造与状态时序，再考虑调整算法。
若要改预处理，对相同输入和相同状态历史比较，分别记录系数、gain、输出及
最终匹配；不要以平均图像误差代替识别表现。若改录入／学习，应验证姿态覆盖、
持久化后再打开的模板、拒绝与取消不写入，以及真实同指／多异指对照。

任何新接受门槛需要有足够异指证据；不要因单次同指失败就降低门槛。
